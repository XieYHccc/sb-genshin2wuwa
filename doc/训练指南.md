数据已经过滤、打包好（`data/30_packed/`），训练脚本、评估面板和推理脚本都写好并做过冒烟测试。本文是在命令行里自己跑训练的逐步手册。具体电脑上的实测数字和进度见 `本地环境与进度.md`。

## 第 0 步：准备

**激活环境**（PowerShell）：

```powershell
.venv\Scripts\Activate.ps1
```

Git Bash 用 `source .venv/Scripts/activate`。激活后命令行前面会出现 `(.venv)`。

**关掉会抢显存和打断训练的东西**：
- 关掉游戏和其他占 GPU 的程序。main 训练（DiT-B）峰值显存约 18 GiB，24 GB 的卡余量不多

- Windows 更新 → 暂停更新，免得半夜自动重启（重启了也不怕，见第 6 步续训，但会浪费时间）

**另开一个终端看 TensorBoard**（同样先激活环境）：

```powershell

```

浏览器打开 http://localhost:6006 。训练开始后曲线和对照图会自动出现，刷新即可。

## 第 1 步：先认清数据现状

| | 原神 | 鸣潮 |
|---|---|---|
| 原始帧（s00 + s01） | 1797 | 1759 |
| 黄昏 / 夜晚，整段排除 | 1018 | 912 |
| 保留：train | 521 帧（含翻转 1042 行） | 607 帧（1214 行） |
| 保留：val | 164 帧 | 150 帧 |

只有一个地貌会话（s01 草原丘陵），每域 500–600 帧训练数据，是计划目标（3000–5000）的 1/6 左右；val 是从 s01 时间末尾临时切的。所以建议的顺序是：

1. **现在**：用现有数据跑 1 个 pilot（ε=0.05、RGB 代价，约 1.5 小时），确认整条链路能出像样的转换，同时看清评估面板怎么读
2. **同时**：在另一台电脑上按 `数据采集指南.md` 补采 s02–s05（注意控制游戏内时间）
3. **补完数据后**：重新过滤、打包（`数据采集指南.md` 最后一节），再做完整的 pilot 扫参和 main 训练

现有数据上的 pilot 结论只能参考：OT 配对的质量取决于数据的多样性，换成 4 种地貌之后，最优的 ε 和 `ot_ratio` 可能会变。

## 第 3 步：第一个 pilot

```powershell
python train.py --run p1_e0.05_rgb --preset pilot --eps 0.05 --cost rgb
```

- DiT-S，16×16 窗口，batch 128，2.5 万步。训练约 1.4 小时，加上评估面板（快速面板每次约 12 s，完整面板每次约 2 分钟）约 1.5 小时
- 每 50 步打印一行：loss、梯度范数、学习率、每步耗时、`F²` 范围、预计剩余时间
- 每 1000 步：固定 τ / 噪声 / 配对上的 train 和 val loss（`[fixed]` 那行）
- 每 2500 步：快速面板（每个方向 32 张 val 帧）；第 12500 步和最后一步：完整面板（全部 val 帧）
- 每 1000 步存一次 `ckpt/latest.pt`，每 5000 步另存 `ckpt/step_*.pt`

## 第 4 步：读结果

### 对照图

`runs/<run>/samples/` 下：
- `panel_<步数>_0to1.jpg`：原神 → 鸣潮；`..._1to0.jpg`：鸣潮 → 原神
- 每行 4 对，每对左边是输入（AE 重建），右边是转换结果
- **看图是最有效的诊断**。重点看：画风变了没有（色调、草的画法、描边、天空）；景物有没有增删、挪位；同一张图里不同区域是否一致

### 终端里面板那几行

```
[panel 0to1] KID×1e3 12.34（identity 40.00 / reinhard 25.00）  struct×1e3 3.21  LPIPS 0.250  ρ 0.42  NN 0.850（参照 0.860）
```

| 指标 | 含义 | 怎么读 |
|---|---|---|
| KID×1e3 | 输出像不像目标域（对比目标域 val 帧） | 越低越好。必须明显低于 `identity`（不转换）和 `reinhard`（全局调色）两个 baseline，否则模型只是在调色 |
| struct×1e3 | DINO self-similarity 距离，结构保留得怎么样 | 越低越好。和 KID 是一对 trade-off |
| LPIPS | 改动幅度 | 本身无好坏，和上面两项一起看 |
| ρ（tone-collapse） | 是不是只调了色 | < 0.15：基本只调色 → 换 DINO 代价或调大 ε；0.25–0.6 正常；> 0.8：结构被大改 → 调小 ε 或提高 `ot_ratio` |
| NN（参照） | 输出到目标域 train 帧的最近邻相似度；参照是真实 val 帧的同一统计量 | NN 明显高于参照 = 在背图（输出"借用"了训练帧的内容） |

样本少（快速面板 32 张，val 才 150 张左右），KID 的抖动不小，看趋势别看单点。另外现在的临时 val 两边内容不一样（鸣潮的 val 主要是金色草地和岩石，原神的是绿草地和湖），KID 的绝对值被内容差异撑大了（不转换的 baseline 都在 300 以上），**只在 run 之间横向比**；补采了 s05 之后才会正常。

### TensorBoard 里值得看的

| 曲线 | 看什么 |
|---|---|
| `train/loss` | 很早就平是正常的（目标里有布朗噪声和随机配对，不可约部分占大头）。跨 ε 的 run 不可比 |
| `calib_Ftarget_m2/b0…b7` | 8 个 τ 桶里回归目标的二阶矩，都应接近 1 |
| `fixed/val_minus_train` | 过拟合警报。持续变大说明在背训练集 |
| `pair/cost_ot` vs `pair/cost_random` | OT 配对的平均代价应明显低于随机配对（RGB 代价下约 0.6 倍） |
| `panel_0to1/*`、`panel_1to0/*` | 上表的指标随步数的变化。**KID 还在降、struct 却开始升** = 开始幻觉或背图，应该停训或回退到更早的 checkpoint |
| `full_*/nfe{4,8,16}_*` | NFE–质量曲线，给实时化定 NFE 用 |
| `full_*/win_*` | 窗口 vs 整帧一致性（plan §5.4），见第 5 步 |

全部数字也逐次追加在 `runs/<run>/metrics.jsonl` 里。

## 第 5 步：pilot 扫参（补完数据之后）

按 plan §5.6 的顺序，一次只改一个旋钮。用 PowerShell 循环可以让几个 run 接着跑（比如睡前启动）：

**第一轮：RGB 代价下扫 ε**（4 个 run，约 6.5 小时）

```powershell
foreach ($e in "0.02","0.05","0.1","0.2") { python train.py --run "p1_e${e}_rgb" --preset pilot --eps $e --cost rgb }
```

**第二轮：RGB vs DINO 代价**（用第一轮选出的 ε，下面以 0.05 为例）

```powershell
python train.py --run p2_e0.05_dino --preset pilot --eps 0.05 --cost dino
```

**第三轮：OT 比例**

```powershell
foreach ($r in "0.6","1.0") { python train.py --run "p3_e0.05_rgb_ot$r" --preset pilot --eps 0.05 --cost rgb --ot-ratio $r }
```

怎么选：把各 run 最后一次完整面板的 KID 和 struct 画在一起（`metrics.jsonl` 里 `"kind": "full"` 的行），KID 和 struct 是 trade-off，选两者都不差、ρ 在 0.25–0.6、对照图最好看的那个；不确定时把对照图发给我一起看。

**pilot 跑完后，做两个测试**：

1. 窗口 vs 整帧一致性（plan §5.4）。完整面板已经算了，看 `metrics.jsonl` 里的 `win_rel_diff`（窗口逐块推理和整帧推理在窗口内部的 latent 差异，占整帧转换改动量的比例）和 `win_tone_shift`（两者在像素上的平均色调差，0–255 尺度）。也可以单独重跑：

   ```powershell
   python train.py --run p1_e0.05_rgb --eval-only
   ```

   `win_tone_shift` 只有 1–2 以内、对照图上看不出差别，main 就只用窗口训练；色调明显偏，main 就加 `--full-every 4`（每 4 步有 1 步用整帧 batch）

2. 转换模型的平移等变测试（plan §8.2），和 AE 自己的曲线对比：

   ```powershell
   python ae_shift_test.py --images data/10_frames/genshin/s00 --n 8 --run runs/p1_e0.05_rgb
   ```

   结果在 `data/shift_test/genshin_s00_p1_e0.05_rgb/`。AE 自己的曲线（已测）在非整 token 平移下约 27–30 dB，转换曲线比它低多少，就是转换模型自己引入的闪烁

## 第 6 步：main 训练

用 pilot 选出的配置（下面以 ε=0.05、RGB、ot_ratio 0.8 为例）：

```powershell
python train.py --run main_e0.05_rgb --preset main --eps 0.05 --cost rgb --ot-ratio 0.8
```

- DiT-B，15 万步，约 21 小时，加评估面板约 22 小时（快速面板每次约半分钟，完整面板每次约 4 分钟）
- 每 5000 步快速面板，每 2 万步完整面板和存档 `ckpt/step_*.pt`（每个约 1 GB）
- 如果第 5 步的一致性测试要求混入整帧：加 `--full-every 4`

### 中断和续训

- 按 **Ctrl+C**：先存 `latest.pt` 再退出
- 断电、蓝屏、重启：最多丢 1000 步
- 续训：**原样再敲一遍同一条命令**，自动从 `runs/<run>/ckpt/latest.pt` 接着跑，TensorBoard 曲线也接得上
- 决定训练目标的超参（模型、ε、代价、`ot_ratio`、batch、学习率……）以 `runs/<run>/config.json` 为准，续训时命令行改不了，改了会打印提示并忽略
- 想多跑一些步：`--steps 200000`；改面板频率：`--panel-every 10000` 之类，续训时可以改

## 第 7 步：用训练好的模型转换图片

```powershell
python translate.py --run runs/p1_e0.05_rgb --input data/10_frames/genshin/s00 --side-by-side
```

- 输入可以是单张图或目录；方向默认按路径里的游戏名推断，也可以 `--direction 0to1`（原神→鸣潮）/ `1to0`
- `--nfe 16` 改 ODE 步数；`--ckpt step_0020000` 用存档的 checkpoint；`--solver heun` 换二阶求解器
- 输出在 `runs/<run>/translate/` 下；`--side-by-side` 输出 `[输入 | 转换]` 拼图

## 常见问题

| 现象 | 处理 |
|---|---|
| `CUDA out of memory` | 先确认游戏和别的 GPU 程序都关了。main 还是爆，可以加 `--bs 96` 新开一个 run（batch 属于训练目标，旧 run 改不了） |
| 每步比预计慢很多 | 看任务管理器里 GPU 是不是被别的程序占着；笔记本 / 台式机的电源模式设成高性能 |
| loss 变成 nan | 停掉，把终端输出和 `runs/<run>/tb` 发给我 |
| 第一次面板很慢 | 正常：第一次要下载 LPIPS 的 AlexNet 权重，并把全部 train 帧解码一遍建评估缓存（`data/30_packed/eval_cache.pt`），之后就快了 |
| 重新打包了数据 | 旧 run 的 `panel_frames.json` 和数据对不上了，新开 run；`data/30_packed/eval_cache.pt` 会自动重建 |
| 启动时出现 `Could not reach the Hub` | 网络抖动，模型权重会自动用本地缓存，不影响训练。断网时可以先在终端里执行 `$env:HF_HUB_OFFLINE=1` 再启动 |
